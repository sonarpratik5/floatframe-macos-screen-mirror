# Popup Handoff

## Product Direction
Popup is a lightweight macOS menu bar utility: **select anything on your Mac and keep it floating while you work**. The core feature is a user-initiated, local-only live mirror of a selected screen region in an always-on-top floating panel.

App Store compliance is the primary constraint. Use public Apple APIs only, keep App Sandbox enabled, and request Screen Recording only because live region mirroring requires ScreenCaptureKit. Do not add Accessibility, Input Monitoring, Apple Events automation, synthetic click forwarding, recording/export, cloud sync, analytics, or network access unless the user explicitly approves a new product direction.

## Privacy / Review Positioning
- Capture is content-agnostic and user-selected.
- Captured pixels stay local; do not save, upload, transmit, analyze, or log captured content.
- Screen Recording permission must be clearly explained before/when needed.
- Mirrored content should be view-only for the App Store MVP. Interacting with the original app through the mirror is out of scope because it likely requires higher-risk permissions.
- Protected/DRM/system-restricted content must remain governed by macOS; do not bypass protections.

## Current Architecture
- `AppCoordinator`: menu bar lifecycle, global shortcut, selection flow, mirror lifecycle, preferences, display changes.
- `SelectionOverlayWindow`: multi-display drag selection with Escape cancellation and first-mouse support.
- `CaptureGeometry`: converts AppKit screen-space selections to display-local ScreenCaptureKit point `sourceRect` plus pixel output sizing, preferring a matching `SCWindow` when selection overlaps a normal window.
- `RegionCaptureSession`: one `SCStream` per mirror, single-window capture when a selected normal window fully contains the region, complete-frame filtering, low queue depth, async teardown.
- `FloatingMirrorPanel`: non-activating always-on-top `NSPanel`, rendering, close/temporary expand/click-through controls, snapping.
- `MirrorPanelLayout`: pure geometry for initial panel sizing, display clamping, and snap targets.
- `CaptureSessionError`: user-facing ScreenCaptureKit permission/entitlement/error messages.
- `ContentView`: Settings UI for Screen Recording guidance, shortcut, appearance, panel width, click-through, launch at login. Opacity is controlled from the menu bar menu in `AppCoordinator`.
- `PopupPreferences`: `UserDefaults`-backed settings.

## Implemented
- Menu bar app with Select Region, settings, close-all, click-through recovery, and Quit.
- Configurable global shortcut, default Shift-Command-P.
- Multi-display region selection overlay with pixel-size label.
- Live region mirror using ScreenCaptureKit, with window-backed filtering for selected window content so later overlapping windows do not cover the mirror.
- Always-on-top movable/resizable non-activating panel across Spaces/full-screen apps, below system menu/status popovers.
- Preserved source aspect ratio and frame-dropping render path via `AVSampleBufferDisplayLayer.sampleBufferRenderer`.
- Persisted opacity, click-through, panel default width, and shortcut preferences.
- Display-change handling and stream failure UI with restart where possible.
- Launch at login via `SMAppService`, with Settings status refreshed when Popup becomes active again.
- UI coverage for accessory launch, core Settings controls, Appearance theme persistence, selection overlay Escape cancellation, and successful drag-selection teardown without invoking ScreenCaptureKit.
- Unit coverage for mirror startup ordering: mirrors are registered only after capture start succeeds, and startup failure does not register a blank mirror.

## macOS 26 Notes
- Target macOS 26.5 behavior: use cooperative `NSApp.activate()`, `orderFrontRegardless()`, and first-mouse overlay handling.
- Do not reintroduce obsolete `CGPreflightScreenCaptureAccess()` / `CGRequestScreenCaptureAccess()` flows. Rely on ScreenCaptureKit permission errors and guide users to Privacy & Security.
- Show mirror panels only after capture starts successfully, so denied permission does not leave a blank floating window.
- Apple’s recommended source-selection UI is `SCContentSharingPicker.shared`. It supports display, window, and application picker modes and reports an `SCContentFilter` through `SCContentSharingPickerObserver`; it does not provide Popup’s current arbitrary rectangle selection. `SCStreamConfiguration.sourceRect` is the public ScreenCaptureKit mechanism for capturing a rectangular display area, and it is ignored for single-window capture. Keep the custom rectangle overlay for the MVP; treat replacing it with the system picker as a product tradeoff, not a pure API migration.

## Capture Geometry Contract
- Selection starts in AppKit global screen coordinates from `SelectionOverlayWindow`: origin is bottom-left/Y-up, with screen frames from `NSScreen`.
- `CaptureGeometry` chooses the `NSScreen` with the largest intersection and clips the selection to that screen. It rejects selections smaller than 8x8 both before and after clipping.
- Display-backed capture uses `SCContentFilter(display:excludingApplications:exceptingWindows:)`. Its `SCStreamConfiguration.sourceRect` must be display-local logical points: `x = selection.minX - screen.minX`, `y = screen.maxY - selection.maxY`, `width/height = selection.size`. Do not pass pixel-space rects to `sourceRect`; that shifts/scales the capture on Retina or scaled external displays.
- Display-backed `SCStreamConfiguration.width` and `height` must remain pixel-sized from the logical source rect multiplied by `NSScreen.backingScaleFactor`, preserving Retina fidelity without changing `sourceRect` units.
- Window matching converts the clipped AppKit selection into CG global coordinates for comparison with `SCWindow.frame`: X is unchanged, Y becomes `primaryDisplayHeight - selection.maxY`. `primaryDisplayHeight` is resolved from `CGMainDisplayID()` rather than `NSScreen.screens.first`.
- Window-backed capture is used only when an on-screen layer-0 `SCWindow` contains the CG-global selection rect, with a 1-point tolerance for fractional frame drift. If no such window matches, fallback is display-backed capture.
- Window-backed capture uses `SCContentFilter(desktopIndependentWindow:)`; `sourceRect` is intentionally unset because ScreenCaptureKit ignores it for single-window streams. Popup crops the selected subregion locally in `MirrorContentView` using `videoCropRect`.
- For window-backed crop math, both the selection and `SCWindow.frame` are in CG global Y-down coordinates. The crop origin is `(selection.minX - window.minX, selection.minY - window.minY) * backingScaleFactor`; crop size is the selected display-region pixel output size.
- `MirrorPanelLayout.videoFrame` positions the full window stream behind the panel bounds using the pixel crop rect. This is what makes selecting a YouTube/video subregion fill the mirror without black margins.
- The known-good behavior after the latest manual check: selecting a browser video region fills the mirror correctly, with no extra positive X/Y offset and no large black area.

## Known Limitations
- Selections spanning displays are clipped to the display with the largest intersection.
- Desktop, wallpaper, menu bar, or multi-window selections fall back to display capture and can still reflect later occluding windows.
- The custom rectangle overlay may be less aligned with Apple’s preferred picker UX than `SCContentSharingPicker`, but the system picker cannot select arbitrary sub-window regions. Retaining the overlay is acceptable for the MVP as long as capture remains user-initiated, local-only, sandboxed, and implemented with public ScreenCaptureKit APIs.
- Click-through passes non-control panel clicks through to underlying apps while preserving access to panel controls.
- Live capture cannot be unit-tested without Screen Recording permission and real system UI state.
- Real ScreenCaptureKit capture-start/mirror presentation still needs manual or permissioned integration validation; live capture depends on Screen Recording permission and real system UI state.
